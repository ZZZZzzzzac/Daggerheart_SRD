## #10 尚未完成的工程项

### 1. 小节锚点还不是真正稳定

当前锚点默认由英文标题生成。英文标题变化时，锚点和外部链接也会变化，不满足“同一大版本内位置稳定”的要求。

渲染核心支持在 Markdown 标题后使用 `{#explicit-id}`，但现有正式正文尚未使用显式锚点。重复锚点当前会自动追加 `-2` 等后缀，PRD 则要求重复位置直接导致构建失败并报告问题。

需要完成：

1. 为当前版本的重要小节建立显式、语言无关的锚点。
2. 构建时拒绝重复显式锚点，不再静默改名。
3. 增加“标题文字变化但锚点不变”的回归测试。

相关代码：`static/js/render-core.mjs`、`scripts/build_srd.py`。

### 2. 处理“敌人与环境”父页面的孤儿正文

以下文件存在：

- `src/pages/adversaries-and-environments/zh.md`
- `src/pages/adversaries-and-environments/en.md`

但 `data/srd.yaml` 将 `adversaries-and-environments` 作为带 `subs` 的目录分组。当前 `flatten_pages()` 遇到分组时只构建子页面，不构建父页面，因此这两份正文不会发布，也不会出现在在线编辑器中。

需要先决定：

- 如果它是正式介绍页，将父页面纳入章节清单、构建、导航、搜索和编辑器。
- 如果它是旧遗留内容，将其移出正式正文目录并保留可恢复归档。

构建系统还应检查未被章节清单引用的正文文件，避免今后再次产生无声遗漏。

### 3. 增加反馈数据库备份流程

反馈保存在 `/var/www/SRD/var/feedback.db`。后台已经支持 JSON 导出，但当前 SRD 与 VPS 仓库中都没有 SQLite 数据库的自动备份、保留策略和恢复说明。

需要完成：

1. 使用 SQLite 在线备份机制生成一致快照，避免直接复制写入中的数据库。
2. 将备份接入服务器定时任务。
3. 明确保留周期、存储位置和恢复步骤。
4. 验证备份不进入公开 Git 仓库或 Web 根目录。

### 4. 正式化版本标识和大版本归档

`data/srd.yaml` 当前仍使用：

```yaml
version: "current"
```

因此反馈记录中的站点版本也只是 `current`，不能准确追溯到具体 SRD 版本或发布版本。仓库目前没有 Git tag。

需要完成：

1. 确定正式版本号命名规则。
2. 让构建产物和反馈记录携带真实版本号。
3. 为大版本发布建立 Git tag 或 GitHub Release 归档流程。
4. 在下一次大版本整体替换前验证归档与恢复流程。

### 5. 补齐自动化测试入口和覆盖范围

`package.json` 当前执行不存在的 `tests/search.test.mjs`，真正的搜索测试文件是 `tests/search_core.test.js`。因此 `npm test` 实际只运行渲染核心测试，没有运行搜索测试。

需要完成：

1. 修正 `npm test`，确保搜索测试实际执行。
2. 增加真实浏览器行为测试，覆盖目录展开与高亮、搜索跳转、语言切换、主题切换和移动端抽屉。
3. 增加端到端发布测试，覆盖编辑正文、完整构建、线上切换、搜索索引更新和反馈位置仍可解析。
4. 增加恶意反馈文本在管理页面中的安全渲染测试。
