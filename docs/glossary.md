# 规则术语与原文摘录

## 内容约束

术语解释只能是规则原文，或用户明确审核通过的文案。不得自行概括、改写或将翻译备注当成规则解释。目前仅实现原文摘录模式，没有任何审核后改写文案，也没有能自动放行自拟解释的开关。

## 名称来源

`data/translation-terms.json` 是用户提供的 `Daggerheart-translator/skills/daggerheart-translation-pipeline/resources/terms-14448.json` 的完整快照，共 328 条。首次导入 SHA-256：`5599B2E3D9177E3FAE15881AFDB2425B4ADDA8BA7CEDD988317423D0AEEAFBB6`。

`data/glossary.yaml` 是阅读站启用条目的白名单，首批仍为 14 个核心术语。`translation_term` 精确选择词表条目，构建时从来源读取 `term`、`translation`、`variants`、`case_sensitive`；不单独编造中英文名称。`note` 仅供维护者判断上下文，绝不展示为规则解释。不要把全部 328 条直接自动标注到正文中：其中有短语、泛义词、语境限定以及重复映射。

快照让服务器构建不依赖本机另一个仓库。更新时从用户指定来源复制文件，核对差异并更新记录；不能把本仓库的副本修改后冒充上游内容。

## 解释来源与校验

每个白名单条目包含 `id`、`translation_term`、`target`、`anchor` 和双语 `quote`。中文逐字摘录 `src/pages/**/zh.md` 的已有译文，英文逐字摘录 `src/pages/**/en.md` 的 SRD 原文。只去除 Markdown/HTML 展示标记、解码字符实体、统一段内空白，不改写任何措辞；相邻段落或列表项以空行分隔。

摘录必须对应指定锚点之后、下一标题之前的一个或多个完整连续段落或列表项。不接受任意半句、跨节拼接或跳过中间条件的拼接。保留所选原文摘录作为可审阅快照；正文变化导致不一致时，构建失败，维护者须重新核对，而不是自动重写解释。

构建会拒绝自拟 `summary`、缺失的双语摘录、重复 ID/别名、缺失目标，以及与指定来源不一致的文字。提示明确标明“本站译文 / SRD 原文摘录”，并提供完整规则来源链接。摘录只展示选中的原文片段，不声称包含完整规则的全部条件。

若中英文实际目标不同，`anchor` 使用 `{zh: ..., en: ...}`。必须核对目标标题和正文，不能只凭锚点拼写判断含义：核心机制页历史上的部分中文锚点与其英文拼写不同。本功能分别定位两个语言的实际小节，不重命名已有锚点。

以后如需更短或更适合提示框的改写文案，应先向用户提交原文、拟议文案与差异，获得明确审核后再增加带审核记录的文案类型；不得自行填写“已审核”。

## 交互与维护

正文标注每个标题小节内每种术语仅首次出现，长词优先，英文遵循来源词表的大小写与变体规则，跳过标题、既有链接、按钮和代码。生成结果携带已转义的原文摘录，不改动 Markdown 正文。

`static/js/terms.js` 将普通链接增强为悬停、聚焦或点击可用的提示框。Tab 可进入来源链接和收起按钮，Escape 或点击外部收起。Ctrl/Cmd 点击仍可正常打开规则。目录下方可关闭提示，偏好仅保存在本地；无 JavaScript 时仍能使用普通规则链接。

在线编辑器继续预览 Markdown，原文一致性校验及术语标注在发布构建时执行。若编辑修改了被引用的段落，发布会被校验拦截；需维护者同步核对 `quote` 后重新发布。

验证：`python -m pytest tests/test_build_srd.py`、`python scripts/build_srd.py`、`npx playwright test tests/browser/terms.spec.mjs --workers=2`。
