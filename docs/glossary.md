# 术语表维护

`data/glossary.md` 是唯一术语表。网站 `/SRD/edit/?path=glossary` 支持搜索、新增、修改和删除，也可直接编辑 Markdown。点击“保存并发布”即可更新网站，不需要手工改源码或部署。

每条术语只有七个字段：英文名、中文名、中文别名、英文别名、大小写、中文解释、跳转链接。没有 ID、英文解释、启停、解释类型或审核记录。英文名写在二级标题中，中文解释放在三级标题后，支持多段文字。

示例：

```md
## 英文名：Example Term

- 中文名：示例术语
- 中文别名：
- 英文别名：Example Terms
- 大小写：不区分
- 跳转链接：

### 中文解释

```

所有条目都参与匹配。中文解释和跳转链接可以留空：没有解释时仅展示中英文名称，没有链接时不显示跳转按钮。中英文阅读界面共用中文解释和跳转链接。别名用中文分号 `；` 分隔，大小写填写“区分”或“不区分”。

优先匹配较长词；同长时完整名称优先于别名，其他冲突按文件顺序取先出现的条目。保留导入词表中的重名和重叠别名，供人工删除、修订，不阻止发布。

解释由用户维护。代理不得自行概括或编写规则解释；现有 14 条中文解释保留从规则正文逐字摘录的文字，其余留空。按用户要求不再设置解释类型、审批字段或自动原文一致性门槛。

表单和 Markdown 使用同一解析器，切换视图与章节会保留当前会话的未发布修改。术语表可与规则正文一起批量发布。版本冲突或构建失败不会覆盖正式文件；发布接口只允许 `data/glossary.md` 这一额外文件，不开放整个 data 目录。

初始 328 条名称和译名来自用户提供的 `Daggerheart-translator/skills/daggerheart-translation-pipeline/resources/terms-14448.json`。当前 Markdown 是人工维护的唯一来源，构建不依赖翻译仓库。
